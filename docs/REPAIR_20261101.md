# Bilibili and media-ownership repair candidate

Base: PR #8 `e46f05cb170ebbb534341ea84cce442a7e6c16cb`. This is a repair stacked above the existing #4–#8 product work, not permission to merge any uncorrected predecessor.

## Changes

- G1: one strict Bilibili parser accepts only HTTPS www `/video/BV...` and `/zh-Hant/video/BV...`. Missing p means 1; malformed, encoded, duplicate, zero, negative and >1000 p values fail closed. Only the zh-Hant `@match` is added; grants/connect/require remain unchanged.
- G2: no reliable active-media CID adapter has been demonstrated. Bilibili SponsorBlock is therefore unavailable, even if an older stored opt-in is true. There are no Bilibili sponsor requests, markers or seeks. INITIAL_STATE/route CID cannot enable it. Speed controls remain usable; no fake player API or added sandbox grant is used.
- G3: Bilibili segment `videoDuration` must be a finite positive number within ±2 seconds of current media duration. Zero, missing, malformed and stale values are rejected for both skip and full labels. Missing/unknown actions never auto-seek. This parser guard is tested but does not re-enable G2.
- Independent review found adjacent blockers in #4–#6: blank/reloading sources retained seek ownership; URL-before-media navigation could mislabel a resume checkpoint; completion margin was inverted; accepted/in-flight sponsor results could reach a changed source. The repair binds tokens to source, route, media and generation, immediately invalidates empty/loadstart windows, and validates at request, response, visual rendering and skip time.
- Sponsor undo exempts the whole segment until playback leaves its interval; a later pass can skip again, and a stale undo cannot seek a replacement source.
- A same-node URL change without a changed media source remains unavailable. This conservative availability trade-off is deliberate; a reused MSE source still needs a verified site adapter.
