# 2026-11-04 快捷鍵一致性與續播修正

基準：main `5ff8456af7a0c21cd8f88c8804d828ea61197c9c`（#14／#15 已合併）。本文件描述未發布候選，不代表 Greasy Fork、瀏覽器或 Tampermonkey 驗收。

## 盤點結果

YouTube、Bilibili、Facebook、Instagram、Threads 原本已共用大部分按鍵。差別不是五套演算法，而是 Bilibili 刻意讓 Tab／Enter 留給原生操作。面板只列部分按鍵，超速與步進又寫死為 5×／0.25×，和設定及 README 不一致。

另有可重現錯誤：未列出的 Alt／Shift 組合誤落入單鍵分支；Shift+Tab 在加速時被當鎖定；長按截圖／PiP 重複執行；零垂直位移的滾輪也降速；按住超速後選新倍率，稍後被舊超速設定覆寫；倍率按鈕提示更新時丟失「設定」與「鎖定」的實際用途。

## 目前共用操作

| 按鍵 | 五站共用效果 |
| --- | --- |
| Backquote（反引號實體鍵） | 按住一般加速，放開回到該影片原基準 |
| Shift + Backquote | 按住設定的超速倍率，放開還原 |
| PageUp／PageDown | 調整設定的加速倍率，預設步進 0.25× |
| Alt + 1–5 | 套用 1–5× |
| Delete | 套用固定 3×，不是刪除或重設設定 |
| Alt + S | PNG 截圖，仍受影片與瀏覽器限制 |
| Alt + P | 子母畫面，仍受瀏覽器限制 |
| Alt + 垂直滾輪 | 依設定步進增減加速倍率 |

同一張 `HOTKEYS` 定義提供事件匹配與完整面板說明，沒有另寫各站鍵位表。一次性動作不因 key repeat 重複執行；只有列出的精確修飾鍵組合生效。Ctrl、Meta、AltGraph、IME、輸入、互動控制與 composedPath 內的輸入元件均退讓；沒有可控制影片就不攔截。

PageUp／PageDown 既有語義保留：原生播放 1×、加速設定 3× 時，PageUp 套用 3.25×，不是 1.25×。明確選倍率會結束超速優先權；若仍按住反引號，放開後仍還原該影片基準，不偷偷轉成永久鎖定。

## 尚保留的兩項原生相容差異

| 操作 | YouTube／Facebook／Instagram／Threads | Bilibili |
| --- | --- | --- |
| 普通 Tab | 暫時加速或鎖定時切換鎖定；待命時不攔截 | 全部保留原生，用面板／浮動倍率鈕鎖定 |
| Enter | 非互動焦點下沿用全螢幕；YouTube 優先點原生按鈕 | 保留原生，不另觸發全螢幕 |

Shift+Tab 在所有站點都不攔截。其他原生方向鍵、Space、F、Esc 亦不新增控制。

**不能把本輪稱為所有按鍵完全一樣。** 若取消這兩個例外，就可能破壞 Bilibili 原生 Enter 或一般鍵盤導航；若改用新的全站 modifier 鎖定／全螢幕鍵，又會改變使用者現有 YouTube 習慣。因此本輪先保留，待確認明確遷移方案再變更。沒有擅自加入新的快捷鍵或可自訂鍵位設定。

## 評委確認的兩個續播缺口

1. 更換播放器：舊程式先讓 media generation 失效，導致後面的 detach 強制存檔被自己的 guard 拒絕。現在先 flush／移除舊 listener，再讓 generation 失效；網址、來源、新分頁紀錄的拒絕條件完全保留，不把舊影片存到新 ID。
2. 手動從頭重播：舊程式只把 `currentTime > 1` 的 seek 視為優先，0–1 秒可能又被續播拉回舊位置。現在任何非 coordinator 持有的 seek 都優先；續播／SponsorBlock 自己的 seek 仍走原有 owner guard，不誤當使用者指令。
